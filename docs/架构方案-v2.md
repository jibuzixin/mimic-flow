## 一、整体架构分层

```
┌──────────────────────────────────────────────────────────┐
│  UI 编排层（可视化拖拽 / 参数配置 / 日志展示）              │
│  输出标准 FlowSchema JSON                                 │
└──────────────────────┬───────────────────────────────────┘
                       │ FlowSchema JSON
┌──────────────────────▼───────────────────────────────────┐
│  调度层 Scheduler（核心）                                  │
│  1. 解析 FlowSchema，构建节点执行图                       │
│  2. 维护单任务全局上下文（变量池 / 执行状态 / 日志）       │
│  3. 原生实现控制流：条件分支 / 循环 / 变量赋值             │
│  4. 连续同引擎节点自动合并为 Segment                       │
│  5. 按节点 engine 类型分发到对应执行引擎                   │
│  6. 统一执行结果回写、错误处理、重试、失败策略             │
│  7. 通过事件总线向 UI 推送实时状态                         │
└──────────┬───────────────────────────┬───────────────────┘
           │ Midscene 节点              │ 扩展节点
┌──────────▼───────────┐     ┌─────────▼─────────────────┐
│  Midscene 执行引擎    │     │  自定义扩展执行引擎         │
│  @midscene/computer  │     │  （nut.js / 系统命令 / …）  │
│  生成 YAML → runYaml │     │  自定义节点类型插件化注册   │
└──────────────────────┘     └───────────────────────────┘
```

### 设计原则

1. **单任务独占**：一台电脑同一时间只能跑一个工作流（鼠标键盘只有一套）
2. **引擎无关**：调度层只认 `FlowSchema`，不关心底层是 Midscene 还是其他引擎
3. **插件化引擎**：新引擎只需实现 `FlowEngine` 接口 + 注册节点类型即可接入
4. **YAML 直通**：Midscene 节点直接生成官方标准 YAML，通过 `runYaml()` 执行，零中间层损耗

## 二、数据格式：FlowSchema JSON

> 这是 UI 层和调度层之间的契约。UI 只需要产出符合此格式的 JSON，调度层就能执行。

### 顶层结构

```typescript
interface FlowSchema {
  version: '2.0';
  flowMeta: {
    name: string;
    desc?: string;
    source?: 'manual' | 'video' | 'nl' | 'file';
    createdAt?: number;
  };

  /** 全局模型配置（调度层会解析并传给对应引擎） */
  modelConfig: {
    /** 默认使用的 midscene 模型 ID（对应设置里配置的模型 profile id） */
    midsceneModelId?: string;
    /** 覆盖特定节点的模型（可选，节点自己指定时优先用节点的） */
  };

  /** 全局变量（用户可在 UI 里定义，节点中用 {{globalVars.xxx}} 引用） */
  globalVars: Record<string, unknown>;

  /** 全局运行时选项 */
  runtime: {
    defaultTimeout: number;     // 节点默认超时 ms
    defaultRetry: number;       // 节点默认重试次数
    onError: 'stop' | 'continue'; // 全局失败策略
  };

  /** 设备/目标配置（决定用哪个引擎） */
  target: {
    type: 'computer';           // 当前 MVP 只做桌面端
    displayId?: string;         // 显示器 ID，默认主屏
  };

  /** 节点列表（按顺序） */
  nodes: FlowNode[];
}
```

### 节点类型

```typescript
type FlowNodeType =
  // --- Midscene 原子操作（engine: midscene）---
  | 'midscene.act'       // AI 自动规划操作（最常用）
  | 'midscene.tap'       // 点击
  | 'midscene.doubleClick'
  | 'midscene.rightClick'
  | 'midscene.hover'
  | 'midscene.input'     // 输入文本
  | 'midscene.clearInput'
  | 'midscene.keyboardPress' // 按键/热键
  | 'midscene.scroll'    // 滚动
  | 'midscene.query'     // 提取信息（返回 JSON）
  | 'midscene.assert'    // 断言
  | 'midscene.waitFor'   // 等待条件
  | 'midscene.sleep'     // 固定等待

  // --- 控制流（调度层原生处理，不进引擎）---
  | 'control.if'         // 条件分支
  | 'control.loop'       // 循环
  | 'control.var'        // 变量赋值

  // --- 扩展节点（自定义引擎）---
  | 'ext.hotkey'         // 系统级热键（nut.js）
  | 'ext.shell'          // 执行系统命令
  | 'ext.file'           // 文件操作
  | 'ext.clipboard'      // 剪贴板操作
  ;
```

### 节点结构

```typescript
interface FlowNode {
  id: string;                         // 节点唯一 ID
  nodeType: FlowNodeType;             // 节点类型
  nodeName?: string;                  // 显示名称
  nodeParams: Record<string, unknown>; // 节点参数（取决于类型）

  /** 后继节点（支持分支） */
  nextNodes: {
    nodeId: string;
    condition?: string;  // 条件表达式（仅 if 节点的后继使用）
  }[];

  /** 节点级运行选项（可选，不填则继承全局） */
  runtime?: {
    timeout?: number;
    retry?: number;
    onError?: 'stop' | 'continue';
  };

  /** 指定引擎（可选，通常由 nodeType 自动推断） */
  engine?: 'midscene' | 'extension';
}
```

## 三、调度层设计

### 核心职责

1. **解析 FlowSchema** → 构建节点图（`nodeId → FlowNode` 映射）
2. **维护执行上下文**：变量池、执行栈、当前节点指针、日志
3. **控制流处理**：if / loop / var 由调度层直接解释执行，不进引擎
4. **节点分发**：根据 `nodeType` / `engine` 决定发给哪个引擎
5. **Segment 合并**：连续的同引擎节点合并成一次引擎调用，减少 overhead
6. **错误 / 重试 / 超时**：统一管理
7. **事件推送**：通过 EventEmitter 把状态推给 UI

### 执行上下文

```typescript
interface ExecutionContext {
  flow: FlowSchema;
  variablePool: Record<string, unknown>;  // 变量池（globalVars + outputs + loop 变量等）
  nodeStates: Map<string, NodeState>;     // 每个节点的执行状态
  currentNodeId: string | null;
  status: 'idle' | 'running' | 'paused' | 'success' | 'failed' | 'stopped';
  startTime: number;
  endTime?: number;
  error?: string;
}

interface NodeState {
  nodeId: string;
  status: 'pending' | 'running' | 'success' | 'failed' | 'skipped';
  startTime?: number;
  endTime?: number;
  output?: unknown;
  error?: string;
  retryCount: number;
}
```

### 调度流程

```
start(flowSchema)
  │
  ▼
初始化 variablePool = { globalVars: flow.globalVars, outputs: {} }
  │
  ▼
找到起始节点（nodes[0] 或标记为 start 的节点）
  │
  ├─────────────────────────────────────────────────────┐
  │                         ↓                           │
  │              取下一个待执行节点                        │
  │                         │                           │
  │          ┌──────────────┴───────────────┐           │
  │          ▼                              ▼           │
  │    控制流节点?                    引擎操作节点?       │
  │      │  yes                           │  yes        │
  │      ▼                                ▼            │
  │  调度层直接解释执行              合并连续同引擎节点为   │
  │  (if/loop/var)                 Segment             │
  │      │                                │            │
  │      │                          ┌────┴────┐       │
  │      │                          ▼         ▼       │
  │      │                   midscene?    扩展引擎?    │
  │      │                      │           │         │
  │      │                      ▼           ▼         │
  │      │                生成 YAML    调用扩展引擎     │
  │      │                runYaml()    execute()       │
  │      │                      │           │         │
  │      └───────────┬──────────┘           │         │
  │                  ▼                      ▼         │
  │          回写结果到 variablePool.outputs[nodeId]   │
  │                  │                                │
  │                  ▼                                │
  │          发送 runtime:node:complete 事件           │
  │                  │                                │
  │                  └────────────────────────────────┘
  ▼
结束 → 发送 runtime:complete 事件
```

### Segment 合并策略

**为什么要合并？** 每次调用 Midscene `runYaml()` 都需要初始化模型连接、截图等开销。把连续的 midscene 节点合并成一个 YAML 一次执行，显著提升效率。

**合并规则**：

1. 连续的 `engine === 'midscene'` 节点合并为一个 Segment
2. 遇到以下情况时断开 Segment：
   - 控制流节点（if / loop / var）
   - 不同引擎的节点
   - 节点有自定义 `timeout` / `retry` / `onError`（与前一个不同）
   - 节点有 `outputVar` 需要立即回写（可选策略：也可以先执行后统一回写）

**Segment 结构**：

```typescript
interface MidsceneSegment {
  engine: 'midscene';
  nodes: FlowNode[];           // 合并的节点列表
  combinedYaml: string;        // 生成的 YAML
  modelConfig: ModelConfig;    // 模型配置
}
```

### 从 FlowNode 生成 YAML 规则

每个 Midscene 节点对应 YAML 中一个 task：

```
node.id → task.name
node.nodeType → 对应 YAML 操作关键字
node.nodeParams → 对应 YAML 参数字段
```

| FlowNode 类型 | YAML 关键字 | 参数映射 |
|--------------|------------|---------|
| midscene.act | aiAct / ai | prompt → 值；deepThink / deepLocate / cacheable → 同级字段 |
| midscene.tap | aiTap | target → 值；deepLocate → 同级 |
| midscene.input | aiInput | target → 值；value → 同级字段 |
| midscene.keyboardPress | aiKeyboardPress | target → 值；keyName → 同级字段 |
| midscene.query | aiQuery | prompt → 值；name → outputVar |
| midscene.assert | aiAssert | assertion → 值；errorMessage → 同级 |
| midscene.waitFor | aiWaitFor | condition → 值；timeout → 同级 |
| midscene.sleep | sleep | duration → 值 |
| midscene.scroll | aiScroll | target → 值；scrollType/direction/distance → 同级 |
| midscene.doubleClick | aiAct | 自动包成 "双击 {target}" |
| midscene.rightClick | aiAct | 自动包成 "右键点击 {target}" |
| midscene.hover | aiHover | target → 值 |
| midscene.clearInput | aiClearInput | target → 值 |

**变量插值**：YAML 生成前，对所有 string 类型的参数做 `{{varName}}` 替换，从 `variablePool` 取值。

**完整 YAML 示例**：

```yaml
computer:
  displayId: 1

tasks:
  - name: node-001 打开浏览器
    flow:
      - aiAct: 按 Cmd+Space 打开 Spotlight
      - sleep: 300
      - aiAct: 输入 "Safari" 并按回车
      - sleep: 2000

  - name: node-002 搜索天气
    flow:
      - aiAct: 点击地址栏
      - aiInput: 地址栏
        value: https://www.bing.com
      - aiKeyboardPress: 地址栏
        keyName: Enter
      - aiWaitFor: 页面加载完成
        timeout: 10000
      - aiAct: 在搜索框中输入 "今日天气" 并按回车

  - name: node-003 提取结果
    flow:
      - aiQuery: 提取天气信息，格式为 { temperature: string, description: string, city: string }
        name: weatherResult
```

### 变量系统

**变量池结构**：

```typescript
variablePool = {
  globalVars: { ... },     // 用户定义的全局变量
  outputs: {               // 节点输出
    [nodeId]: any,         // aiQuery、aiString 等的返回值
  },
  loop: {                  // 循环迭代变量
    [loopNodeId + '_i']: number,
  },
  system: {                // 系统变量
    flowName: string,
    startTime: number,
    platform: 'darwin' | 'win32' | 'linux',
  },

```

**引用方式**：`{{globalVars.xxx}}`、`{{outputs.nodeId.field}}`、`{{loop.i}}`、`{{system.platform}}`

**插值时机**：
- 控制流表达式：调度层直接求值（expr-eval）
- 节点参数：传给引擎前统一替换

## 四、执行引擎设计

### 设计原则

- **全插件化、平级关系**：所有引擎都是 `FlowEngine` 接口的实现，没有主次之分
- **注册发现**：通过 `EngineRegistry` 注册和查找引擎
- **节点→引擎映射**：通过节点类型前缀或显式 `engine` 字段匹配引擎
- **懒加载初始化**：引擎在第一次被使用时才初始化
- **单次执行内复用**：同一次工作流执行中，引擎实例复用，执行结束统一释放

### 引擎接口

```typescript
interface FlowEngine {
  /** 引擎唯一标识，如 'midscene'、'nutjs'、'shell' */
  name: string;

  /** 引擎显示名称 */
  displayName: string;

  /** 支持的节点类型模式（支持前缀匹配，如 'midscene.*'） */
  supportedNodeTypes: string[];

  /** 初始化引擎（懒加载，第一次使用时调用） */
  initialize?(config: EngineInitConfig): Promise<void>;

  /**
   * 执行一段连续的同引擎节点
   * @param segment 待执行的节点段
   * @param context 执行上下文（变量池、模型配置等）
   * @param signal 中止信号
   * @param onEvent 事件回调（节点开始/完成/日志/截图等）
   */
  executeSegment(
    segment: FlowNode[],
    context: ExecutionContext,
    signal: AbortSignal,
    onEvent: (event: EngineEvent) => void,
  ): Promise<SegmentResult>;

  /** 获取本引擎的报告文件路径（如 Midscene HTML 报告） */
  getReportPath?(): string | null;

  /** 释放资源（工作流执行结束时调用） */
  dispose?(): Promise<void>;
}

type EngineEvent =
  | { type: 'node:start'; nodeId: string }
  | { type: 'node:complete'; nodeId: string; output?: unknown }
  | { type: 'node:error'; nodeId: string; error: string }
  | { type: 'log'; level: 'info' | 'warn' | 'error'; message: string; data?: unknown }
  | { type: 'screenshot'; nodeId?: string; dataUrl: string };

interface SegmentResult {
  success: boolean;
  outputs: Record<string, unknown>; // nodeId → 输出值
  error?: string;
}
```

### 引擎注册中心

```typescript
class EngineRegistry {
  private engines: Map<string, FlowEngine> = new Map();

  /** 注册引擎 */
  register(engine: FlowEngine): void;

  /** 注销引擎 */
  unregister(name: string): void;

  /** 获取指定名称的引擎 */
  get(name: string): FlowEngine | undefined;

  /** 根据节点类型查找匹配的引擎 */
  findEngineForNode(nodeType: string): FlowEngine | undefined;

  /** 列出所有已注册引擎 */
  list(): FlowEngine[];

  /** 释放所有引擎 */
  disposeAll(): Promise<void>;
}
```

### 节点与引擎的映射规则

1. **优先使用节点显式指定的 `engine` 字段**
2. **否则按节点类型前缀匹配**：
   - `midscene.act` → 匹配 `supportedNodeTypes: ['midscene.*']` 的引擎
   - `nutjs.hotkey` → 匹配 `supportedNodeTypes: ['nutjs.*']` 的引擎
   - `shell.exec` → 匹配 `supportedNodeTypes: ['shell.*']` 的引擎
3. **找不到时报错**：明确提示用户该节点类型无对应引擎

### Midscene 引擎实现

**包**：`@midscene/computer`

**核心实现思路**：

```typescript
class MidsceneEngine implements FlowEngine {
  name = 'midscene';
  displayName = 'Midscene 桌面引擎';
  supportedNodeTypes = ['midscene.*'];

  private agent: ComputerAgent | null = null;
  private reportMerger: ReportMergingTool | null = null;
  private segmentCount = 0;

  async initialize(config: EngineInitConfig) {
    // 初始化报告合并器
    this.reportMerger = new ReportMergingTool();

    // 构造 Midscene 模型配置
    const modelConfig = this.buildModelConfig(config);

    // 创建 agent
    this.agent = await agentForComputer({
      displayId: config.displayId,
      generateReport: true,
      modelConfig,
      aiActionContext: config.actionContext,
    });
  }

  async executeSegment(nodes, context, signal, onEvent) {
    // 1. 变量插值
    const interpolated = interpolateNodeParams(nodes, context.variablePool);

    // 2. 生成 YAML
    const yaml = generateMidsceneYaml(interpolated);

    const startTime = Date.now();
    try {
      // 3. 执行
      const { result } = await this.agent!.runYaml(yaml);

      // 4. 追加到报告合并器
      if (this.agent?.reportFile) {
        this.reportMerger!.append({
          reportFilePath: this.agent.reportFile,
          reportAttributes: {
            testId: `segment-${this.segmentCount++}`,
            testTitle: nodes.map(n => n.nodeName || n.id).join(' → '),
            testDescription: `包含 ${nodes.length} 个节点`,
            testDuration: Date.now() - startTime,
            testStatus: 'passed',
          },
        });
      }

      return { success: true, outputs: result };
    } catch (e) {
      // 失败也追加报告
      if (this.agent?.reportFile) {
        this.reportMerger!.append({
          reportFilePath: this.agent.reportFile,
          reportAttributes: {
            testId: `segment-${this.segmentCount++}`,
            testTitle: nodes.map(n => n.nodeName || n.id).join(' → '),
            testStatus: 'failed',
            testDuration: Date.now() - startTime,
          },
        });
      }
      return { success: false, error: String(e), outputs: {} };
    }
  }

  getReportPath() {
    if (!this.reportMerger) return null;
    return this.reportMerger.mergeReports('workflow-report', {
      rmOriginalReports: true,
      overwrite: true,
    });
  }

  async dispose() {
    // computer 模式不需要显式释放 agent
    this.agent = null;
    this.reportMerger = null;
  }

  private buildModelConfig(config: EngineInitConfig) {
    const defaultModel = config.models.default;
    return {
      baseURL: defaultModel.baseUrl,
      apiKey: defaultModel.apiKey,
      model: defaultModel.modelId,
      modelFamily: defaultModel.modelFamily,
      timeout: defaultModel.advanced?.timeout,
```

### Nut.js 扩展引擎实现

对于 Midscene 不擅长或不支持的系统级操作，用 nut.js 实现：

```typescript
class NutjsEngine implements FlowEngine {
  name = 'nutjs';
  displayName = 'Nut.js 系统引擎';
  supportedNodeTypes = ['nutjs.*'];

  private handlers: Map<string, NodeHandler> = new Map();

  constructor() {
    // 注册内置处理器
    this.handlers.set('nutjs.hotkey', new HotkeyHandler());
    this.handlers.set('nutjs.clipboard', new ClipboardHandler());
    // ...
  }

  async executeSegment(nodes, context, signal, onEvent) {
    const outputs: Record<string, unknown> = {};
    for (const node of nodes) {
      const handler = this.handlers.get(node.nodeType);
      if (!handler) throw new Error(`Unknown node type: ${node.nodeType}`);

      onEvent({ type: 'node:start', nodeId: node.id });
      try {
        const result = await handler.execute(node.nodeParams, context, signal);
        outputs[node.id] = result;
        onEvent({ type: 'node:complete', nodeId: node.id, output: result });
      } catch (e) {
        onEvent({ type: 'node:error', nodeId: node.id, error: String(e) });
        throw e;
      }
    }
    return { success: true, outputs };
  }
}
```

**MVP 阶段内置扩展节点**：

| 节点类型 | 实现方式 | 说明 |
|---------|---------|------|
| nutjs.hotkey | nut.js keyboard | 系统级热键（如全局截图快捷键） |
| nutjs.clipboard | nut.js clipboard | 剪贴板读写 |

### Agent 复用策略

**设计**：一次工作流执行内复用，执行结束统一释放。

```
工作流执行开始
  │
  ├── EngineManager 初始化
  │
  ├── 执行过程中：
  │   ├── 遇到 midscene 节点 → 懒加载 MidsceneEngine → 创建 agent → 复用
  │   ├── 遇到 control 节点 → 调度层直接处理
  │   └── 遇到 nutjs 节点 → 懒加载 NutjsEngine → 复用
  │
  └── 执行结束 → EngineManager.disposeAll() → 释放所有引擎
```

**理由**：
- 单任务模型：同一时间只有一个工作流在跑，不需要对象池
- 引擎数量少：MVP 阶段 2-3 个引擎
- agent 创建成本低：`agentForComputer()` 主要是初始化配置，不启动额外进程
- 同执行内复用：已避免频繁创建销毁

## 八、关键技术选型

| 技术 | 选型 | 理由 |
