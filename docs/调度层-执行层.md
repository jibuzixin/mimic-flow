# Midscene可视化编排桌面端 MVP 自底向上技术方案

前置约定

1. 技术栈：Electron + React + ReactFlow
2. 分层顺序（自底向上）：Midscene适配层 → 流程调度运行时（调度器核心） → IPC通信协议 → UI画布层
3. 核心目标：调度器作为中间枢纽，补齐Midscene原生缺失的**流程控制能力（分支、循环、变量、异常、重试）**；定义唯一标准中间介质 `Flow JSON`；所有模块解耦。
4. 参考Midscene核心边界（依据文档）
   - Midscene擅长：页面导航、aiTap/aiInput/aiQuery/aiAssert、截图、页面AI推理；
   - Midscene原生模型：单次执行一段连续操作，**不支持if分支、循环、跨步骤变量传递、多节点失败策略**；没有长流程状态管理。
   - Midscene输入形式：任务描述字符串 / yaml任务描述，串行执行一段动作；执行结束返回本次任务所有结果。

---

## 第一层：Midscene 适配封装层（调度器最底层依赖）

### 定位

不直接在调度器内部硬编码调用Midscene SDK，单独封装适配层。职责：

1. 接收调度器下发的**分段任务指令**；
2. 组装Midscene运行上下文、模型配置、actionContext；
3. 调用Midscene执行；
4. 标准化统一输出执行结果、截图、推理日志、页面数据；
5. 捕获Midscene原生异常，向上抛出标准化错误。

### 对外接口（极简）

```
interface MidsceneAdapter {
  runTask(task: MidsceneSegmentTask): Promise<MidsceneSegmentResult>
}
```

#### MidsceneSegmentTask（调度器下发给适配层，一段连续无分支线性动作）

> 
> 关键规则：**调度器遇到分支、循环边界时，必须切分成独立分段任务**

```
interface MidsceneSegmentTask {
  // 模型配置（支持全局/单流程覆盖）
  modelConfig: {
    modelName: string
    apiKey: string
    baseUrl: string
    deepThink: boolean
    cacheable: boolean
    timeout: number
  }
  // Midscene内置上下文
  actionContext: string
  // 线性原子动作数组，直接翻译成Midscene可执行描述/YAML
  actions: FlowAtomNode[]
  // 设备环境
  deviceConfig: DeviceConfig
  // 变量快照：当前分段执行前变量池快照，用于变量插值渲染
  variables: Record<string, any>
}
```

#### MidsceneSegmentResult（向上返回调度器）

```
interface MidsceneSegmentResult {
  success: boolean
  error?: {
    message: string
    code: string
  }
  // aiQuery提取出来的数据
  extractData: Record<string, any>
  // Midscene原生日志、截图列表
  logs: MidsceneRawLog[]
  screenshots: string[] // 本地文件路径
}
```

> 
> 重要约束：**适配层完全不理解分支、循环逻辑**，只执行一段连续线性动作；流程控制全部交给上层调度器。

## 第二层：核心——流程调度运行时（调度器）

### 调度器核心职责（如何赋能Midscene，解决原生短板）

1. **解析标准FlowJSON完整拓扑结构（节点、连线、条件）**
2. 维护全局**变量池**：跨节点数据传递、变量插值、存储aiQuery结果、用户自定义变量
3. 实现原生缺失流程语义：
   - if 条件分支路由
   - for循环 / while循环迭代控制
   - 单节点独立重试、全局失败策略（终止/跳过/跳转捕获节点）
   - 节点独立超时管控
   - 异常捕获链路
4. **拓扑分片：把带分支循环的完整Flow，在运行时切割成一段段【线性无分支任务】**，交付给Midscene适配层执行
5. 接收底层Midscene执行结果，更新变量池，根据执行结果与分支条件，决定下一个执行节点
6. 执行状态统一管理，向上推送实时运行事件给UI画布
7. 支持任务中断、停止、暂停（MVP优先实现停止）

### 调度器运行核心循环

```
1. 初始化：加载FlowJSON、初始化变量池、初始化设备/模型配置
2. 定位当前待执行节点
3. 渲染节点内所有变量插值（{{var.key}}）
4. 判断节点类型
   a. 普通AI操作节点：持续收集相邻连续线性节点，直到碰到分支入口/循环边界 → 打包为SegmentTask下发Midscene
   b. if判断节点：读取变量池，计算条件表达式，选择下一条分支，**不调用Midscene**
   c. 循环节点：判定循环条件，满足则跳转循环起始节点，不满足则走出循环
   d. 捕获节点：接收上游失败事件，执行预设恢复逻辑
5. 接收Midscene返回结果 → 更新变量池（aiQuery输出存入指定变量key）
6. 推送节点执行事件（开始/成功/失败、截图、日志）至UI
7. 循环直至没有下一个节点 → 流程结束
```

> 
> 核心设计巧思：
> Midscene只负责“页面干活”；**所有控制流逻辑100%在调度器内部实现**。Midscene完全不知道上层存在循环、分支。

## 标准 Flow JSON 完整 Schema（MVP最小可用版本）

> 
> 唯一标准协议：画布产出JSON → IPC → 调度器解析；视频解析模块输出同结构JSON。
> 所有输入源归一为此结构。

```
interface FlowSchema {
  // 流程基础元信息
  flowId: string
  flowMeta: {
    name: string
    desc: string
    // MVP只实现manual手动触发；cron/http二期
    triggerType: "manual"
    globalTimeout: number // 整个流程最大执行时长 ms
    globalRetry: number // 节点默认重试次数
    failStrategy: "terminate" | "skip" // 全局默认失败策略
  }

  // 设备配置：Web/Android/iOS，直接透传给Midscene
  deviceConfig: {
    type: "web" | "android" | "ios"
    url?: string
    viewport: { width: number; height: number }
    userAgent?: string
    cookiePath?: string
  }

  // AI全局配置（Midscene运行模型，视频解析模型放在全局软件配置，不属于Flow）
  aiGlobalConfig: {
    modelName: string
    apiKey: string
    baseUrl: string
    actionContext: string
    defaultDeepThink: boolean
    cacheable: boolean
    timeout: number
  }

  // 全局变量池定义（画布配置）
  globalVars: Array<{
    key: string
    value: string | number | boolean
    encrypt: boolean // 敏感变量标记，存储加密
  }>

  // 全部节点列表（核心拓扑）
  nodeList: Array<FlowNode>
}

interface FlowNode {
  nodeId: string
  nodeType:
    // 原子操作节点（会被打包送入Midscene）
    | "navigate"
    | "aiTap"
    | "aiInput"
    | "aiQuery"
    | "aiAssert"
    | "sleep"
    // 流程控制节点（调度器本地计算，不发给Midscene）
    | "if"
    | "loop"

  nodeName: string
  timeout: number // 当前节点独立超时，覆盖全局
  retryCount: number
  failStrategy?: "terminate" | "skip"

  // 节点输出结果存入变量key（aiQuery专用）
  outputVar?: string

  // 节点专属参数，根据nodeType区分结构
  nodeParams: Record<string, any>

  // 拓扑连线：当前节点执行完成后，可以去往哪些节点（支持多分支）
  nextNodes: Array<{
    nodeId: string
    // 条件表达式；空=无条件跳转
    condition?: string
  }>
}
```

### 关键字段说明 & MVP约束

1. **区分两类节点**
   - 操作节点：产生页面动作，最终会组装进Midscene分段任务
   - 控制节点（if/loop）：仅调度器内部逻辑，**永远不会下发给Midscene**
2. `nextNodes` 实现分支能力
   - if节点携带多条nextNodes，每条附带condition表达式；调度器执行表达式筛选通路
3. 变量插值规范统一：模板语法 `{{globalVars.xxx}}`
 调度器在执行节点前统一预渲染替换文本，再送入Midscene任务

### nodeParams 示例定义（MVP）

```
// aiTap
{ locate: string }
// aiInput
{ locate: string, text: string }
// aiQuery
{ dataDemand: string, schemaDesc: string }
// aiAssert
{ assertion: string }
// sleep
{ duration: number }
// if
{ expr: string }
// loop
{ expr: string, maxIteration: number } // 最大循环次数防死循环
```

## 第三层：IPC通信协议（UI渲染进程 ↔ 调度运行时（主进程））

Electron架构：

- 渲染进程：React+ReactFlow画布UI
- 主进程：启动调度运行时、文件处理、视频解析服务
通信采用**请求-响应模型 + 主动事件推送**，定义标准化消息体，避免散乱裸IPC调用。

### 消息通用外层封装

```
interface IpcMessage<T> {
  event: string
  payload: T
  requestId?: string // 用于异步请求响应配对
}
```

### 1）UI → 调度器【请求类接口】

1. `flow:run`
payload：{ flowJson: FlowSchema }
功能：启动一条流程执行
返回：{ runInstanceId: string }
2. `flow:stop`
payload：{ runInstanceId: string }
功能：强制终止正在运行的流程
3. `flow:validate`
payload：{ flowJson: FlowSchema }
功能：调度器预校验FlowJSON合法性（变量、循环配置、节点参数），提前反馈错误给画布

### 2）调度器 → UI【主动推送事件（实时数据流）】

执行期间持续推送，前端画布监听渲染状态、日志、高亮节点

1. `runtime:node-start`

```
{
  runInstanceId: string
  nodeId: string
}
```

2. `runtime:node-success`

```
{
  runInstanceId: string
  nodeId: string
  extractData?: Record<string, any>
  screenshots: string[]
  logs: LogItem[]
}
```

3. `runtime:node-fail`

```
{
  runInstanceId: string
  nodeId: string
  error: string
  screenshots: string[]
  logs: LogItem[]
}
```

4. `runtime:flow-finish`

```
{
  runInstanceId: string
  success: boolean
  reportPath: string // 生成HTML报告本地路径
}
```

### 4）多模态模块IPC（UI ↔ 主进程视频解析服务）

> 
> 视频解析模块独立，**不属于调度运行时**（属于输入预处理层）
> 事件：`video:parse-flow`
> 入参：视频本地路径
> 出参：标准FlowSchema（线性节点，无分支循环）
> 前端接收后自动渲染ReactFlow画布。

> 
> 重要分层隔离：
> 视频解析模型调用逻辑在【输入预处理模块】；
> Midscene视觉模型调用逻辑在【调度器→适配层】；两套模型配置独立存储在软件全局设置，完全分开。

## 第四层：UI画布层（ReactFlow）双向数据转换规则

### 两个核心转换函数（MVP必须实现）

1. `graphDataToFlowSchema(graph): FlowSchema`
ReactFlow内部图形结构 → 标准FlowJSON
规则：

- 每个ReactFlow Node映射为 FlowSchema.nodeList 一条记录
- ReactFlow Edge（连线）解析，组装到对应节点 `nextNodes[]`，携带条件
- 画布侧边栏全局配置映射：deviceConfig / aiGlobalConfig / globalVars

2. `flowSchemaToGraphData(flow): ReactFlow GraphData`
标准FlowJSON → 画布图形
用途：

- 打开本地保存流程文件
- 视频解析完成返回FlowJSON，自动渲染画布

约束：

- 视频解析输出只有线性节点（不含if/loop），用户只能在画布手动新增控制节点；
- 画布层**禁止实现任何执行逻辑**，仅序列化、编辑、转发消息。

## 数据流完整闭环汇总（自底向上串联）

### 链路A：画布手动编排执行

```
ReactFlow画布 → graphDataToFlowSchema → IPC发送flow:run
→ Electron主进程调度器接收FlowJSON
调度器解析拓扑、维护变量池、遍历节点
遇到线性操作节点集合 → 组装MidsceneSegmentTask → Midscene适配层
→ Midscene执行
结果逐层向上回传 → 调度器推送runtime事件 → UI画布高亮节点、展示日志截图
```

### 链路B：视频导入自动生成流程

```
UI上传视频 → IPC调用视频解析模块
视频切片 → 调用【多模态流程解析模型】
模型返回动作列表 → 构造标准FlowSchema（线性）
FlowSchemaToGraphData → 画布自动渲染节点
用户编辑新增分支/循环 → 保存/运行，复用链路A
```

## MVP阶段明确技术取舍（控制工作量）

1. 表达式引擎：MVP仅实现简单布尔条件 `{{var.xxx}} == "abc"`，不做复杂嵌套表达式；
2. 循环只支持最大迭代次数限制，防止死循环卡死；
3. 不实现子流程、插件系统（调度器架构预留字段，代码骨架搭建，功能延后）；
4. 变量仅支持基础类型：字符串、数字、布尔；不支持复杂嵌套对象深度插值；
5. 日志只本地持久化，不上传云端；
6. 暂停功能砍掉，仅支持【停止】运行。

# 一、先确认已达成的三条技术决议

1. 条件表达式：引入轻量表达式库（推荐 `expr-eval`），不自研表达式解析；
2. 本地持久化：文件后缀 `.flow.json`；存储层增加抽象接口，未来可无缝切换存储格式/数据库；
3. Midscene指令生成：调度器组装结构化动作数组，最终拼接为自然语言任务文本交付 Midscene，暂不构建完整YAML对象树。

# 三、两处关键顶层补充，不在FlowJSON内部，但是配套规范

## 1. 文件包装层（重要！满足你「未来更换格式留出余地」需求）

**不要直接把 FlowSchema 裸写入 `.flow.json`**
外层增加包装对象，未来可以兼容加密、压缩、格式迁移：

```
// 本地 .flow.json 文件最外层结构
interface FlowFileWrapper {
  schemaFormat: "midscene-desktop-flow"; // 文件类型标识
  schemaVersion: "1.0.0"; // 文件格式版本
  payload: FlowSchema; // 真正的流程内容
}
```

好处：

- 读取时先校验 `schemaFormat`，防止打开非法文件；
- 后续如果想改成二进制/加密格式，可以新增 `schemaFormat`，代码分支兼容旧`.flow.json`；
- 序列化、反序列化统一封装一个 `FlowFileService`，所有读写走这个类，底层实现随时替换。

## 2. 区分两套模型配置存储位置（非常容易混淆，再次固化规范）

> 
> ⚠️ **【重点】不要把视频解析模型放入 FlowSchema**

1. FlowSchema -> aiGlobalConfig：**Midscene运行视觉模型**（每条流程可单独覆盖）
2. 视频解析多模态模型：**保存在软件全局配置（Electron本地全局配置文件）**，不属于单个流程，不存入 `.flow.json`
原因：视频解析属于**编辑阶段能力**，不是流程运行时配置；一条流程运行时不会调用视频解析模型。

# 四、MVP 阶段字段使用规则（约束开发，避免范围膨胀）

1. **所有标记【预留扩展】字段：Typescript接口定义保留，但前端画布不提供编辑入口，调度器读取到直接忽略；**
2. `version` / `schemaVersion` 强制写入，后续迭代变更JSON结构时用于做**数据迁移脚本**，避免旧流程文件打不开；
3. `disabled`、`tags`、`catchNodeId` 一期代码存在但是不实现功能；
4. 表达式统一语法规范：
变量访问统一：`globalVars.xxx`
示例：`globalVars.username == "test"`
调度器执行前，使用 `expr-eval` 编译执行；
5. 变量插值语法保持：`{{globalVars.xxx}}`
   - 插值：调度器**字符串预渲染**（替换文本），交给Midscene
   - 条件分支：交给 `expr-eval` 表达式引擎解析，**不走插值替换**> 
   > 两套机制分开，避免冲突。

# 五、当前 FlowJSON 结构还缺少什么吗？总结判断

在 **MVP范围** 内：
✅ 完整覆盖：画布编排、分支、循环、变量、单节点策略、模型配置、设备配置
✅ 支持视频解析输出线性FlowJSON自动渲染画布
✅ 调度器可以完整解析拓扑，分片生成Midscene任务
✅ 文件外层包装预留格式迁移能力
✅ 版本字段支持未来结构升级迁移

**MVP无需继续新增字段。**
后续二期扩展能力（子流程、插件节点、异常捕获、环境区分）可以再追加字段，现在强行加入只会增加开发负担。
