## 二、核心协议

### 1. FlowSchema JSON

工作流的标准数据格式，定义了节点、连接、变量等信息。

```typescript
interface FlowSchema {
  flowId: string;
  flowMeta: {
    name: string;
    desc: string;
    tags: string[];
    version: string;
    createdAt: string;
    updatedAt: string;
  };
  nodes: FlowNode[];
  target: { type: 'computer' | 'web'; url?: string };
  runtime: { defaultTimeout: number; defaultRetry: number; onError: 'stop' | 'continue' };
}
```

### 2. IPC 通信协议

前端与主进程通过 Electron IPC 通信：

| 通道 | 方向 | 用途 |
|------|------|------|
| `store:get` | 前端 → 主进程 | 获取存储配置 |
| `store:set` | 前端 → 主进程 | 设置存储配置 |
| `store:clear` | 前端 → 主进程 | 清空所有数据 |
| `flow-v2:run` | 前端 → 主进程 | 运行工作流 |
| `flow-v2:stop` | 前端 → 主进程 | 停止工作流 |
| `flow-v2:status` | 前端 → 主进程 | 获取工作流状态 |
| `flow-v2:event` | 主进程 → 前端 | 推送运行时事件 |
| `dialog:select-folder` | 前端 → 主进程 | 选择文件夹 |
| `shell:open-path` | 前端 → 主进程 | 打开系统文件夹 |
| `app:get-default-paths` | 前端 → 主进程 | 获取默认存储路径 |

### 3. RuntimeEvent 事件格式

调度层向 UI 推送的事件格式：

```typescript
type RuntimeEvent =
  | { type: 'flow:start'; flowId: string }
  | { type: 'flow:complete'; status: 'success' | 'failed' | 'stopped'; duration: number; reportPath?: string }
  | { type: 'node:start'; nodeId: string; nodeType: string; nodeName?: string }
  | { type: 'node:complete'; nodeId: string; duration: number; output?: unknown }
  | { type: 'node:error'; nodeId: string; error: string; willRetry?: boolean }
  | { type: 'log'; entry: LogEntry }
  | { type: 'screenshot'; nodeId: string; dataUrl: string };
```

### 4. 模型配置协议

#### ModelProfile

模型配置文件：

```typescript
interface ModelProfile {
  id: string;
  name: string;
  provider: string;
  tags: ModelTag[];          // 多标签：multimodal, text, asr, tts
  baseUrl: string;
  apiKey: string;
  modelId: string;
  modelFamily: string;
  enabled: boolean;
  pricing: ModelPricing;
  timeout?: number;
  retryCount?: number;
  reasoningEnabled?: boolean;
  cacheable?: boolean;
}
```

#### DefaultModelSelection

默认模型选择：

```typescript
interface DefaultModelSelection {
  defaultMultimodal?: string;                    // 简单设置的默认模型
  executionEngines: ExecutionEngineConfig;       // 高级设置的执行引擎模型
}

interface ExecutionEngineConfig {
  midscene: EngineModelConfig;
}

interface EngineModelConfig {
  defaultModelId?: string;    // 默认模型（必选）
  insightModelId?: string;    // 视觉定位模型（可选）
  planningModelId?: string;   // 规划模型（可选）
}
```

## 三、核心流程

### 工作流执行流程

```
UI 触发运行
    ↓
构建 FlowSchema JSON
    ↓
IPC 发送 flow-v2:run
    ↓
FlowScheduler.start()
    ↓
遍历节点执行
    ├── 控制节点 → 直接执行（条件/循环/变量/日志）
    └── 引擎节点 → 合并连续同引擎节点为 Segment
                      ↓
                EngineRegistry.executeSegment()
                      ↓
                MidsceneEngine.runYaml()
                      ↓
                生成 HTML 报告
                      ↓
                推送节点完成事件
    ↓
工作流完成/失败/停止
    ↓
推送 flow:complete 事件
    ↓
UI 更新状态
```

### 模型配置优先级

```
工作流模型配置 > 高级设置（执行引擎）> 简单设置（默认模型）
```

## 四、注意事项

### 1. 模型同步

- 简单设置的默认模型会同步到高级设置的 Midscene 默认模型
- 高级设置的 Midscene 默认模型会同步到简单设置的默认模型
- 两者保持一致，消除歧义

### 2. YAML 生成格式

- 相同引擎的连续节点会合并到一个 task 的 flow 中
- 使用 `@midscene/core/report` 的 `ReportMergingTool` 合并多个 segment 的 HTML 报告
- 避免生成多个独立的 HTML 报告

### 3. 节点状态更新

- 每个节点开始执行时推送 `node:start` 事件
- 每个节点执行完成时推送 `node:complete` 事件
- 节点失败时推送 `node:error` 事件，支持重试
- UI 层根据事件实时更新节点状态（运行中/成功/失败）

### 4. 停止按钮

- 点击停止按钮会调用 `flow-v2:stop` IPC
- 主进程调用 `FlowScheduler.stop()` 设置 `status = 'stopped'`
- 通过 `AbortController` 取消正在执行的引擎操作
- 前端收到响应后更新 `isRunning = false`

### 5. 存储路径

- 默认路径：`~/Library/Application Support/mimic-flow/logs` 和 `~/Library/Application Support/mimic-flow/workflows`
- 点击"打开"按钮会自动创建目录并打开系统文件管理器
- 用户可自定义存储路径

### 6. 双重后台端口

启动服务时会看到两个端口：
- Vite 开发服务器端口（前端）
- Electron 应用本身

这是正常现象，Vite 用于热更新，Electron 运行桌面应用。

### 7. 权限要求

- **屏幕录制权限**：Midscene 需要访问屏幕截图
- **辅助功能权限**：控制鼠标键盘操作
- **文件系统权限**：读写工作流和日志文件

### 8. 错误处理

- 节点失败会根据 `runtime.defaultRetry` 配置自动重试
- 所有节点失败后工作流终止
- 错误信息会通过 `node:error` 事件推送到 UI
- 失败节点会在画布上显示红色错误提示

## 五、开发指南

### 启动开发环境

```bash
npm run dev
```

### 构建生产版本

```bash
npm run build
npm run dist:mac    # macOS
npm run dist:win    # Windows
npm run dist:linux  # Linux
```

### 代码规范

- 使用 TypeScript，确保类型安全
- 前端使用 shadcn/ui 组件库
- 状态管理使用 Zustand
- 代码风格遵循 ESLint 配置
